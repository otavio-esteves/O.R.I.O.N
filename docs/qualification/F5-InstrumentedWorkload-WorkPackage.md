## HOST protocol v2 and dependencies

`f5_instrumented_workload_protocol.py` defines an additive closed plan/checkpoint/journal. All existing v1 files and validators remain unchanged. `InvocationJournal` reuses only the v1 store's anchored inode/dir-fd, O_NOFOLLOW, single-link ownership, flock, fsync/rename primitives. It writes a new-only v2 store and never reconstructs an executable controller from evidence. A failed ACK is not adopted or retried.

Plan identity is sourceCommit, complete sourceManifestSha256, appSha256, testSha256, nullable modelSha256/modelSizeBytes pair and nullable configurationSha256. These are references, never profile authority. Model size is independent expected metadata and is never filled from SOURCE. Target identity/build/API/ABI/page size is checked against real read-only device observations. Every limit and both finite schedules are explicit: durationMillis, transportTimeoutMillis, maximumObservationGapMillis, minimumAttemptIntervalMillis, resourceExitCooldownMillis, maximumResourceDeaths, maximumStartLatenessMillis; workOffsetsMillis and observationOffsetsMillis. Work offsets are exclusive of the deadline; the explicit final observation may occur at the deadline. No supplied field chooses a prompt, model to load, tokens, threads or resource budget.

The plan also requires `bootstrapOperation=NONE|CORE_ONCE`, with no default. CORE_ONCE explicitly selects one original Core invocation before the measured window, in the same Main/Owner/graph; NONE does not bootstrap. Worst-case record budget is `8 + 3 * (workCount + bootstrapCount) + 2 * observationCount <= 4096`, where bootstrapCount is zero or one. Each event is at most 4096 bytes; the upfront byte reservation is `16384 + recordBudget * 4096 <= 20 MiB`. The additive journal has a 20 MiB limit and its enclosing store a separate 20 MiB + 1024-byte read bound; plan/checkpoint parsing keeps its smaller bounds. These are HOST evidence bounds, not Binder limits. Oversized output halts uncertainty rather than truncating/replaying. At most 256 selected WORK offsets and one separately identified BOOTSTRAP are consumed once. An integrity-only `invocationFenceSha256` binds the selected call; it is not `admissionDecisionSha256`, an Android capability or a resource decision.

The fixed new framework runner is `network.orion.qualification.test/network.orion.app.compatibility.OrionCortexInstrumentedWorkloadInstrumentation`. Its only argument names are orionOperation (OPEN/BOOTSTRAP/WORK/OBSERVE/CLEANUP), orionRunId, orionFixtureId, orionSessionId and orionAttemptId with exact operation-specific presence. BOOTSTRAP and WORK require their own attempt UUID. IDs are technical UUID association, not authority. `--no-restart` requires bounded ASCII real `am help` support and the explicit instrumented-foreground procedure. The HOST pins kernel boot, boot count, MAIN PID and readable process start ticks; unavailable identity refuses rather than assuming PID continuity. OPEN is a control checkpoint before the workload window. The executor never starts/replaces MAIN; an explicitly selected BOOTSTRAP asks the retained Owner for one original Core invocation without requiring a prior AI sample.

The result Bundle has `orionWorkloadCheckpoint`, fixed stream `ORION_WORKLOAD_CHECKPOINT`, optional runtime status and optional SOURCE. Only the exact terminal framework framing is accepted, with no trailing result/status/error lines. The checkpoint has schemaVersion=2/kind=ORION_F5_INSTRUMENTED_CHECKPOINT, operation/runId/fixtureId/attemptId/sessionId, stamp, outcome/refusal/failureCode/ownerCallInvoked/executionState, resources/observation/resourceExit/policyFacts, nullable actual model/configuration/source digests and ten false approval flags. A MAIN-minted graph nonce (`sessionId`) exists only in RAM/transport; the journal retains sessionIdSha256. Configuration binding is observed from MAIN trusted composition, never an echo of HOST approval.

The additive `settlement` field is ORIGINAL_UNLOAD_CONFIRMED, NO_OWNER_CALL or UNPROVEN. NO_OWNER_CALL requires the actual current program's issued=false witness; an Owner refusal after entering Owner is not NO_OWNER_CALL. ORIGINAL_UNLOAD_CONFIRMED requires the retained original capture receipt with known identity, no invalidation and original UNLOAD_TRUE_CLEANUP/UNLOADED marker, plus actual scalar idle and an empty diagnostic lane. SOURCE presence/completeness, HOST timestamps and logical terminal alone never establish unload. Missing/lost/malformed framing, transport interruption or unproven settlement aborts UNKNOWN, without retry. A known refusal/failure is preserved and stops preparation.

`configurationSha256` identifies `ORION_INSTRUMENTED_RESOURCE_DESCRIPTOR_V1`, assembled inside the actual Owner from its immutable ordered fallback plans, resource timing, identical selected template reference and explicit capture-observation configuration. ## Observation, uncertainty and cleanup

WORK has one thread/transport slot. During blocked WORK, the independent HOST schedule issues only fixed read-only OS queries and records WORK_INFLIGHT gaps; it never launches concurrent instrumentation into that MAIN. Idle OBSERVE requests actual MAIN read-only metrics on the existing endpoint, never binds/restarts AI or reevaluates policy. The first actual complete observation is required before WORK; stale/no-complete observations cannot become an invocation permission. Gaps remain visible even if later samples recover.

A local transport timeout kills only its own HOST client, not Android, and leaves the workflow UNKNOWN. It never means Core TIMED_OUT or remote termination. UNKNOWN prevents subsequent observation instrumentation, work and cleanup. Constructor/BaseException and partial worker-start paths preserve evidence/ownership and cannot release a slot for a replacement worker. Reopening an interrupted store never resumes work.

Cleanup is separately selected after halt/expiry and is not constrained by the former work deadline. It requires the same actual graph/target/artifacts, no active/uncertain invocation and matching owned markers. It removes only this run's diagnostic buffers/markers; it never closes shared Owner, resets history, deletes models/business state or resolves UNKNOWN. A cleanup failure is retained, not automatically retried. Evidence is preserved. Missing RAM-only graph nonce after abrupt HOST death does not authorize reconstructing a WORK token from a journal.

A completed finite schedule is not automatically the target elapsed duration. The report/journal distinguishes an insufficient source span and explicit gaps. Neither before/after observations nor HOST elapsed time prove continuous queue coverage, autonomy or physical qualification.

A cold configured graph with no existing authenticated AI endpoint cannot produce a complete initial PSS observation. With NONE, the executor therefore refuses WORK; it does not bind from OBSERVE or invent zero AI PSS. With explicit CORE_ONCE, BOOTSTRAP_INTENT receives a durable ACK before one call into the same original Owner path. All original Core checks remain inside that invocation. The bootstrap counts toward conservative death/cooldown/cadence accounting; after proven success/unload/idle, HOST waits the already explicit minimumAttemptIntervalMillis and obtains a real complete OBSERVE before starting the timed window. Bootstrap time, SOURCE and results do not count toward the requested window or 24h source span. No profile or operating values are supplied by this operation.

Publication uses a pinned Linux O_TMPFILE inode with no named fallback for initial creation; state replacement is acknowledged only after the actual published inode/content, fsync and current directory binding are verified. Substitution or uncertainty requires inspection and retains evidence. Independent transport cleanups all run; the identical original interruption takes precedence over cleanup errors. Owned cleanup records UNKNOWN best effort and propagates the identical original non-Exception interruption.
