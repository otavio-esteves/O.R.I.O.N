# ORION-F3-TASK-009 — Durable MAIN task runtime and native UI

Issue: https://github.com/otavio-esteves/O.R.I.O.N/issues/40

OBJECTIVE: Connect the existing deterministic task pipeline to MAIN recovery, durable UI ingress and a native task screen. Users can create, list, complete and cancel tasks with exact human confirmation and replay-safe results.
FILES ALLOWED: app MAIN runtime/admission/task kernel/adapters/UI binding and related tests; core command/query task UI ports and receipt contracts; feature/tasks module; narrow existing action receipt/DAO query extensions; build/dependency files; narrow core/health and feature/diagnostics technical counts/readiness; README/documentation/evidence.
CONTRACTS INVOLVED: StartupBarrier/IngressCoordinator/DurableIngressQueue; MAIN lifecycle and verified durable UI origin; exact original confirmation receipt; ActionEngine/Skill ownership; GetTasks; conservative abandoned-action recovery; bounded retention/capacity. Architecture §§48–61 and Master Plan §§9.1–9.2 apply.
INVARIANTS INVOLVED: INV-001/004/007/008/009/011/014/018/019/021/022/023/029/030/031/033/035/036.
TESTS REQUIRED: gated enqueue/no effect; authenticated durable replay and fresh presence; original receipt timestamp/expiry and exact fingerprint/version; lifecycle revocation; same outer ingress/action/effect/event/audit transaction; transient failures preserve queue; permanent rejection rolls back effects; duplicate/conflict; read queries have no mutation; MAIN-only readiness/capability and auxiliary ownership; Compose create/confirm/list/complete/cancel/recreation; Docker check/build/lint/boundaries; host SIGKILL/new-PID harness.
ACCEPTANCE CRITERIA: Actual UI effects traverse durable ingress/policy/action/owned Skill, after recovery and through one real barrier. Confirmation is never fabricated by queue drain. Sensitive payloads encrypted/minimized; selected UI DTOs reveal no storage or authority ports. No automatic retry of uncertain actions; no full F4/physical qualification claim.
OUT OF SCOPE: Scheduler/reminder/worker implementation, generic external dispatcher, AI/voice, schema/process/IPC/security authority change and deferred physical S21 qualification #23.

PROCESS DEATH / SECURITY / MIGRATION: The generic encrypted ingress row and local action preparation/effect share one writer transaction. Rollback restores QUEUED and the original action; a committed confirmation/effect exposes success together. Original receipt timestamps survive replay and expire after 60 seconds. A verified decrypted queue callback supplies origin; fresh focused/resumed/unlocked presence remains a separate policy check. Correlation metadata does not change canonical replay material. Confirmations persist action references plus receipts, not another title copy. Failed storage gates further execution and exposes diagnostics/retry. No new schema, process, IPC, Android permissions or exported component. Retention uses existing bounded 90-day key-aware pruning; pending events and manual/UNKNOWN actions are retained, never automatically replayed. ResourceGovernor still denies inference; no reminder/worker producer is installed. Full F4 recovery/event publication/scheduling and physical qualification remain open.

UI INSETS: Explicit adjustResize, one root Scaffold IME admission and consumed inner padding prevent the keyboard from collapsing the task list. The screen has no second IME padding. See Android's [edge-to-edge setup](https://developer.android.com/develop/ui/compose/system/setup-e2e) and [inset consumption contract](https://developer.android.com/develop/ui/compose/system/insets-ui). The visual test scrolls to the exact synthetic task/confirmation and checks asynchronous readiness before interaction; unrelated pending requests are preserved.

STARTUP/UI: A render-only recovery-publication key reloads safe task reads after cold startup finishes, even when the Tasks destination was restored before the kernel was available. It does not grant authority. Transient drafts survive this reload; a work counter keeps controls busy while recovery and a user callback overlap. A read-only fake-port UI regression proves the cold-start reload and draft preservation without submitting mutable commands.

VALIDATION: Canonical Docker check/debug/release/AAB/native and dependency gates passed (4m14s), with 301 JVM cases and zero failures/errors. Final frozen-source focused unit/build/lint checks passed; matching final APKs passed all 144 app Android cases plus four unchanged Keystore Android cases on API35/x86_64. Host RUN_AS_SIGKILL/new-PID task transaction rollback/replay passed with the same APK hashes. UI cases cover cold-start reload/draft preservation and actual create/confirm/recreate/complete/cancel.
